# 検証範囲

GitHub ActionsのCIでは、Windows / LinuxとNode.js 22 / 24の組み合わせで `npm ci`、型チェック、以下のテストを実行します。

`npm test` は実SQLite・HTTP・CLIを使い、以下を確認します。

- 通常フォルダを指定した初回起動、自動初期化、再起動、二重起動拒否、ポート競合後の回復。
- 強制終了後のロック自動回収とデータ保持、複数プロセスの同時回収でも起動は一つだけになること。
- 生存PID・確認不能PID・破損ロックの自動削除拒否、SIGHUPハンドラによる停止と排他解放（実際のバツ閉じ通知・停止完了はOS依存）。
- サーバ側連絡帳の登録・更新・検索・ページング、未登録アドレスへの直接送信。
- `xxx@xxx` の正規化、自分宛てだけの軽量一覧・全文取得・既読／未読更新。
- 一覧・本文取得が自動既読にしないこと、CLIの明示的な `--mark-read`。
- A → B → Aと返信への再返信、親参照・件名・会話IDの継承。
- 並行送信と再送の二重保存防止、キーの競合、受信者以外の本文取得・状態更新・返信の拒否。
- ページサイズ1〜200の制限、順序、カーソルのアドレス／条件への紐付け。
- 別フォルダの利用者から設定ファイルなしで接続、日本語stdin・UTF-8ファイル・短文引数。
- 既存の無関係フォルダ・未対応スキーマのDBの保護、接続ファイル破損の明示失敗、再起動でのトークン維持。
- トークン・Host・Originの制限、JSON・UTF-8・入力サイズ・不明な項目の拒否。
- 接続不能・不正応答・タイムアウトが成功や空一覧にならず、送信の再試行キーを保持すること。

`npm run test:package` はtgzから二つの別プロジェクトへ実インストールし、配布スキルをそれぞれの `.github\skills\agent-post` に配置できることと、配布版サーバの初回起動・health・連絡帳・送受信・返信を確認します。WindowsではWindows PowerShellのUTF-8パイプも通します。配布物への実データ・接続情報の混入も確認します。

これらは実際のAIによる宛先判断、カスタムエージェント定義の自動読み込み、自動起動、通知、他マシン・ネットワーク共有・敵対的なローカル利用者間の分離を保証しません。実エージェントでの操作確認は [試行手順](trial.md) を使ってください。
